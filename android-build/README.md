# Android APK/AAB Build

This directory contains documentation for building Android APKs and App Bundles for VeloxMD.

## Overview

Android APK and App Bundle artifacts are automatically built and published as release assets whenever a new GitHub release is published. The process is managed by the GitHub Actions workflow at `.github/workflows/build-android.yml`.

## Platform Support

**Note:** VeloxMD is primarily designed for Linux desktop. Android support is experimental and may have limitations:

- Small screens may require UI adjustments
- Touch input handling differs from desktop
- Some desktop-specific features may not be available
- File access on Android requires permissions

## Artifacts Generated

When you publish a new release, the following are built and uploaded:

### APK (Android Package)
- **File:** `veloxmd-release-v{version}-universal.apk`
- **Use Case:** Direct installation on Android devices
- **Compatibility:** Works on all Android API versions specified in pubspec
- **Installation:** `adb install veloxmd-release-v{version}-universal.apk`

### AAB (Android App Bundle)
- **File:** `veloxmd-release-v{version}.aab`
- **Use Case:** Distribution through Google Play Store
- **Optimization:** Device-optimized APKs are generated by Google Play
- **Recommended:** For production releases to app stores

## How It Works

### Automated Build (GitHub Actions)

When you publish a new release on GitHub:

1. The `build-android` workflow is triggered
2. Java SDK is installed (Temurin 17)
3. Flutter builds the release APK
4. Flutter builds the App Bundle
5. Artifacts are renamed with version tag
6. Both are uploaded as release assets

### Local Build (Manual)

To build Android artifacts locally:

1. **Prerequisites:**
   - Flutter SDK installed and configured
   - Java SDK 17+ installed
   - Android SDK and tools installed
   - Valid keystore for signing (for production)

2. **Build APK:**
   ```bash
   flutter build apk --release
   # Output: build/app/outputs/flutter-apk/app-release.apk
   ```

3. **Build App Bundle:**
   ```bash
   flutter build appbundle --release
   # Output: build/app/outputs/bundle/release/app-release.aab
   ```

4. **Install APK on Device/Emulator:**
   ```bash
   adb install -r build/app/outputs/flutter-apk/app-release.apk
   flutter run --release
   ```

## Android Configuration

### Minimum API Level
- Check `android/app/build.gradle` for `minSdkVersion`
- Typical: API 21 (Android 5.0 Lollipop)

### Target API Level
- Check `android/app/build.gradle` for `targetSdkVersion`
- Should match latest stable Android API

### Permissions
- File access permissions declared in `android/app/src/AndroidManifest.xml`
- Markdown file picker requires `READ_EXTERNAL_STORAGE`
- Runtime permissions handled by `file_picker` package

### Signing
- Release APKs are automatically signed with default keystore
- For production: Configure custom signing in `android/key.properties`
- See [Flutter Android Signing](https://docs.flutter.dev/deployment/android) for details

## Release Process

To publish a new Android release:

1. **Create a new release on GitHub:**
   ```bash
   git tag -a v0.5.0 -m "Release v0.5.0"
   git push origin v0.5.0
   gh release create v0.5.0
   ```

2. **The workflow automatically:**
   - Builds APK and AAB
   - Uploads both as release assets

3. **Download:**
   - Users can download APK/AAB from GitHub Releases page
   - APK: `veloxmd-release-v{version}-universal.apk`
   - AAB: `veloxmd-release-v{version}.aab`

## Testing

### On Physical Device

```bash
# Connect device via USB (with ADB enabled)
flutter run --release

# Or install APK directly
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

### On Emulator

```bash
# Start emulator first
flutter emulators --launch emulator-name

# Then run
flutter run --release
```

## Distribution

### Google Play Store
1. Build AAB: `flutter build appbundle --release`
2. Sign with proper keystore (see Flutter docs)
3. Upload to Google Play Console
4. Configure store listing and release

### GitHub Releases
1. APK automatically uploaded to releases
2. Users download directly from GitHub
3. No store distribution needed

### Direct Installation
1. Share APK via email, messaging, or file transfer
2. Enable "Unknown Sources" in Android Settings
3. Tap APK to install

## Troubleshooting

### Build Fails
- Verify Java is installed: `java -version`
- Check Android SDK: `flutter doctor`
- Update dependencies: `flutter pub get`

### APK Not Generated
- Check build output: `build/app/outputs/flutter-apk/`
- Verify build script didn't error
- Try clean rebuild: `flutter clean && flutter pub get`

### Installation Fails
- Ensure device is connected: `adb devices`
- Install with replace: `adb install -r app-release.apk`
- Check Android version compatibility

### Signing Issues
- Verify keystore exists and is accessible
- Check keystore properties in `android/key.properties`
- See [Flutter Signing Documentation](https://docs.flutter.dev/deployment/android)

## Performance Tips

- APK size can be optimized with `--split-per-abi`
- AAB provides better size optimization on Play Store
- Release builds are significantly faster than debug
